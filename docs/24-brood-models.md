# 24 · Brood models

The Brood is the swarm faction of Grubcraft. Its units are insects and insect-like creatures: ants, beetles, mantises, moths, crickets and a centipede, plus three heroes who lead them. This document covers its fifteen 3D models: how they are made, where the sources live, and the numbers behind them. The look itself is described in [09 · Art and Audio](09-art-and-audio.md).

**Built so far:** all fifteen models are built to final quality and listed in `assets-src/models.ron`. The game draws a model for every unit listed in `data/units.ron`. The Skitterlings are the only Brood unit listed there today, so they are the only Brood model drawn in play (see [Known limits](#known-limits)).

## What this is

The Brood's style is called Hive lacquer. The creatures follow real insect anatomy: glossy chitin (the hard outer shell of an insect), amber plate edges, bruise-purple joints, larval cream and a teal sheen. Their light is Grub lime. Three things carry the look across all fifteen models:

- **Grub lime glow** lights the eyes, throats and glowing sacs of the units.
- **Warning-stripe team colour bands.** Team colour is the colour of the player who owns the unit. Each model paints it in bands, like a warning stripe, on the abdomen, wing-cases or cloth, so you can tell whose unit it is at a glance. Everything else keeps its own colour.
- **Readable chestnut chitin.** The first dark palette read too dark at battle-camera range. So the shells are chestnut with amber edges, which stay readable from far away.

The fifteen models cover the whole roster: a worker, two light units, two heavy units, a support beetle, ranged acid-ants, spear mantises, air moths, a siege engine, a monster, summoned larvae and three heroes.

The Skitterlings first used a CC0 Alien Bug model by CDmir as a stand-in. CC0 is a licence that lets anyone use a file freely. The Brood's own model replaces it, so the Brood no longer uses the Alien Bug. All Brood models are made for Grubcraft, and no outside model files are used for them.

## How they are made

Each model is made by a Python script rather than by hand in a 3D editor, so anyone can rebuild it and get the same result. Unlike the Concord models, the Brood does not start from Quaternius bodies. Every Brood model has its own rig, built by its script from a shared kit. The steps, in order:

1. **Blender, run from code.** Blender is an open-source 3D modelling program. We use its Python module, `bpy`, which is installed with pip into a virtual environment (a private folder of Python packages called `bvenv`). Each script builds one model from nothing.
2. **Its own rig, from a shared kit.** A *rig* is the skeleton of bones inside a model that moves its skin. The shared kit, `bk.py`, holds the `Creature` class (the code that keeps one creature's parts and bones together), geometry builders for lofted bodies (a body made by stretching a series of cross-sections along a line, like a loft in a 3D editor), segmented plates, domes, horns, membranes and a materials palette. Each leg is a four-bone chain: coxa, femur, tibia and tarsus, which are the hip, thigh, shin and foot of an insect leg. The script solves each leg with two-link *inverse kinematics* (IK), which works out the joint angles needed to put the foot where it should go, so the feet stay planted.
3. **High-poly build with procedural materials.** Each model is first built as a detailed high-poly mesh (a mesh is the surface of the model, made of triangles; high-poly means many of them). Its materials, such as glossy chitin, amber plate edges, cream larval skin and glow, are *procedural*: generated by code from rules, not painted by hand.
4. **Standard clips.** The clips are generated frame by frame and written as plain keyframes (poses set at fixed moments, which the game fills in between), so the game needs no IK at run time. `bugclips.py` makes the standard eight clips (Idle, Walk, Run, Attack, Attack2, Hit, Die and Cheer) for the six-legged units. They walk with a *tripod gait*, a pattern in which three legs swing while the other three keep the body up. Units add Shoot or Block themselves.
5. **Game mesh and baked maps.** `lowpoly.py` turns the high-poly build into a much simpler game mesh. It lays out a UV atlas (the flat map that tells each texture where it sits on the mesh), then *bakes* the surface detail into texture images, which means it copies the detail onto the simpler mesh. The maps are colour, team (which parts take the team colour), normal (fake surface bumps for light to catch), ORM (occlusion, roughness and metalness, which control how light sits on the surface) and emissive (where the model glows). Emission is baked as colour only, so the lime glow is written into the colour itself.
6. **Four levels of detail, then the pack.** `gc_artbake` makes four versions of each model with fewer triangles each. LOD 0 (level of detail 0) is the closest and most detailed, and LOD 3 is the simplest, for the farthest view. It then writes all the models into `assets/models.pak`, the pack the game reads.

## Budgets

Every model is held to a *budget*: a maximum triangle count for each of its four LODs. The bake checks each level against its budget. The budget depends on what kind of unit the model is.

| Budget class | Models | LOD 0 | LOD 1 | LOD 2 | LOD 3 |
|---|---|---|---|---|---|
| Soldier (worker, light, heavy, support, ranged, spear, air and summoned units) | Gnawer, Skitterlings, Chitin Guard, Reclaimer, Spitters, Burrowers, Mantid Reapers, Shellbacks, Drone-Moths, Spawnlings | 8,400 | 3,000 | 1,000 | 350 |
| Hero | The Queen-in-Waiting, The Devourer, The Whisperer | 12,000 | 4,000 | 1,400 | 450 |
| Single big model | Broodmother Bulk, Colossus Maw | 20,000 | 7,000 | 2,400 | 800 |

The other limits are the same as for the other rosters:

- **One material per model.**
- **Maps at 512 × 512** pixels in the game. The baker shrinks larger maps to this size.
- **Up to 63 bones** per rig. The Brood's rigs use between 11 and 36.

**Height rule.** A model's height in `assets-src/models.ron` is set from its size in its rest pose, which is the neutral pose it stands in before any animation. The usual rule takes the height of the smallest box that holds the model in that pose, multiplies it by 1.6, and divides by 2.64. This is the rule the Yari Ashigaru was scaled with (see [22 · Concord models](22-concord-models.md)). Every Brood model then gets one more step: its height is 1.5 times the usual result. Insects are small by nature, and at the battle camera they would vanish at the usual size. Proportions between Brood units are unchanged, so a Gnawer stays much smaller than a Colossus Maw.

## Where the sources live

The sources live in the shared project folder, not in the repository.

- **Build scripts and helpers:** `/mnt/project-files/design/faction-looks/brood-roster/source/`. One script per unit is in `units/`. The helpers are `bk.py` (the Brood kit: the Creature class, the body, plate, dome, horn and membrane builders, and the materials palette), `bugclips.py` (the standard clips and the tripod gait) and `lowpoly.py` (high-poly to game mesh and maps).
- **Blender files:** the Blender file for each model is in `blends/`, beside `source/`.
- **Facts for each model:** `facts.json`, in the same roster folder, with the name, slug, triangle and bone counts, height, budget class, clips and script for every model.
- **Review renders:** `/mnt/project-files/design/faction-looks/brood-roster/review/`, with renders for checking each model.
- **Game-ready files** (the glb model and its PNG maps: albedo, team, normal, orm and emissive): `/mnt/project-files/assets-src/grubcraft/brood/<slug>/`.

## Rebuilding one model

The build tools need Blender's Python module, installed with `pip install bpy` into the `bvenv` virtual environment. They need no Quaternius files, because every Brood rig is built by its own script.

1. From the `source/` folder, run the model's script in `units/` with Blender's Python. It builds the model as a Blender file. Then run `lowpoly.py` on the result, which makes the game mesh and its maps. The script name for each model is in `facts.json` (for example `gnawer` or `chitin_guard`).
2. Run `gen_models.py` from `source/` (it reads `units.json`). It copies the baked model and its maps to `/mnt/project-files/assets-src/grubcraft/brood/<slug>/` and writes the model's entry in `assets-src/models.ron`, with the height rule above and the budget for its class. `bake.sh` and `rv.sh`, beside it, run the build and bake steps and make a review sheet.
3. Check the model's entry in `assets-src/models.ron`, including its path, height and maps.
4. From the repository root, run `cargo run --release -p gc_artbake`. This rewrites `assets/models.pak` and `assets/models.manifest`. Commit those with the `models.ron` change, as [09 · Art and Audio](09-art-and-audio.md) describes.

**Merge conflicts.** `models.pak` is a packed file, so never merge it by hand. If two branches both change it, merge main, keep both sides' entries in `models.ron`, run `gc_artbake` again to rebuild the pack, and commit the new pack.

## Known limits

- **Only the Skitterlings of the fifteen is drawn in the game today.** The game draws models only for units listed in `data/units.ron`, and the Skitterlings are the only Brood unit listed there. The other fourteen appear in the `--showroom all` view, which shows every model.
- **Surface relief comes from baked normal maps.** The ridges, grooves and plate edges look raised because the normal maps fake bumps for light to catch. They are not real geometry, so they do not change the outline of a model.
- **The models are first-pass final art.** They are built to final quality, but they may still get a polish pass once the Brood has been seen in play.
- **Drone-Moths hover only because every clip lifts them.** The rest pose stands on the ground. The game has no flying layer yet, so the clips alone make them hover.
- **The Colossus Maw's legs do not step.** They ride on the spine bones, so its feet are not planted on the ground the way the six-legged units' feet are.
